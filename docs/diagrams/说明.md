# 图与源文件

`docs/diagrams/` 放两类文件，**成对出现、同名**：

| 文件 | 作用 | GitHub 会渲染吗 |
| --- | --- | --- |
| `xxx.drawio` | 源文件，用 draw.io 桌面版打开继续改 | **不会** |
| `xxx.svg`（或 `.png`） | 从 draw.io 导出的图，**文档里引用的是它** | **会** |

## 为什么不能直接引用 `.drawio`

GitHub 的 markdown 只渲染浏览器认识的图片格式：`png`、`jpg`、`gif`、`svg`、`webp`。
`.drawio` 是 draw.io 自己的 XML，GitHub 只把它当成一个普通文件（点开是下载或源码），
所以必须**先导出成图，再引用那张图**。

## 导出设置（draw.io 桌面版）

File → Export as → **SVG**：

- **取消勾选** "Include a copy of my diagram"，否则源数据会再塞进 SVG，体积翻倍
- **Text Settings 选 "Text as SVG"**，不要选 "Text as HTML"。GitHub 会清理 SVG 里的
  HTML 与脚本，选 HTML 时文字可能整片不显示
- 需要留白就不要勾 "Crop"
- 想要位图就导 **PNG**，并把 **Zoom 调到 200%**，在高分屏与手机上才不糊

## 引用方式

源文件与导出图放同一目录，文档里用相对路径引用导出图：

```markdown
![架构分层](diagrams/架构分层.svg)
```

## 和 mermaid 的关系

能用 mermaid 表达的图（流程、时序、类关系）**优先用 mermaid**：它写在 markdown 里，
GitHub 原生渲染，不用导出、不会不同步。

draw.io 留给 mermaid 画不好的那些：分层架构总览、需要精确排版的示意图。
这种情况下**必须连源文件一起提交**，否则以后没人能改它。

## 可以直接复用的现成图

仓库历史里有两张手绘的 draw.io，排版比 mermaid 自动布局好，可以导出后使用：

| 源文件 | 页 | 适合放在哪 |
| --- | --- | --- |
| `Class Diagram.drawio` | `01 核心类关系` | `项目说明.md` 的「类关系图」一节（导出前建议先按代码核对，见下） |
| `Class Diagram.drawio` | `02 H.264 子系统` | 不要用，对应的模块没有接入链路 |
| `全流程.drawio` | 第 1 页 | 架构或全流程总览的候选；但它是 WebSocket 之前的版本，且缺 eventfd 回投那一跳 |

导出后放到本目录，源文件也一并复制过来（同名成对），然后替换文档里对应的引用即可。

**已核对出的偏差**（供改图时参考）：`Server → ThreadPool` 是组合不是聚合（构造 `new`、
析构 `delete`）；`Channel` 反过来持有 `Epoll*`；`EventLoop` 只在 `wakeupChannel_` 上拥有 Channel；
类图缺 WebSocket 那一整套（`processWebSocketFrames` 等）与背压字段（`in_flight_requests_`）；
全流程里「回调函数将任务分发给线程池」已过时（现在直接在 EventLoop 线程调 `business()`）。
